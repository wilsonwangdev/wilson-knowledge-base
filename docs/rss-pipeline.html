归属：Quartz 内置 vs 定制

组件来源说明

NewsletterFooter ★ 定制 站点内邮件订阅表单，POST 到 follow.it API
关键认知：Quartz 的 RSS 输出是「原样照搬页面 HTML」。它不做任何内容处理和清洗。heading 后的锚点 SVG 是 rehype-autolink-headings 等插件自动生成的页内导航元素，在邮件客户端中完全没有意义。邮件渠道的内容清洗是我们加的，不属于 Quartz 功能范围。

Bug 回顾：为什么第一次修复没生效

时间线

Commit动作问题

fc0079c 添加 cleanHtml() 清洗函数 放错了位置 — 在 createURLEntry 中调用，此时 richContent 已被 escapeHTML() 处理

执行顺序对比

❌ fc0079c（第一次修复）

  • toHtml() → 原始 HTML
  • escapeHTML() → &lt;a&gt;
  • cleanHtml() → 匹配不到！
  • 结果：锚点 SVG 原样编码后漏出

✅ 3f62ec7（最终修复）

  • toHtml() → 原始 HTML
  • cleanHtml() → 剥除 <a role="anchor">
  • escapeHTML() → 编码 (已干净)
  • 结果：RSS 不含锚点 SVG
教训：HTML 文本处理必须关注编码状态。正则匹配的是字符序列，而 &lt;a 和 <a 是不同的字符序列。在对 HTML 做正则清洗时，务必在编码之前操作原始字符串。

最终代码

quartz/plugins/emitters/contentIndex.tsx

// ★ 定制：清洗函数 — 必须在 escapeHTML 之前调用
const cleanHtml = (html: string): string => {
  return html.replace(/<a\s+role="anchor"[^>]*>.*?<\/a>/g, "")
}

// emit() 中构建 richContent 时
richContent: opts?.rssFullHtml
  ? escapeHTML(cleanHtml(toHtml(tree as Root, { allowDangerousHtml: true })))
  : undefined,
//           ^^^^^^^^
//           先清洗原始 HTML，再编码

quartz.config.ts — 开启 RSS Full HTML

Plugin.ContentIndex({
  enableSiteMap: true,
  enableRSS: true,
  rssLimit: 50,
  rssFullHtml: true,   // ← 关键：输出完整 HTML 正文
})
